# Skill — UX testing

## Trigger

Use for user-testing plans, task scripts, session notes, research analysis and retesting. For a review based only on code/screenshots, use `ux-review` or Part 4C.1 `usability-heuristics` instead. For WCAG conformance, use Part 4C.2 accessibility procedures.

## Minimal loading

Read `.aiassistance/ux/testing/README.md`, then only the applicable study, moderation, evidence or synthesis guide. Use existing platform guides and the design system *only* when the task needs them. Do not load all of `.aiassistance/` for every session.

## Steps

1. Establish decision, target user, platform/build, supported features and known unknowns.
2. Select method and representative participant groups; mark hypothetical work separately.
3. Create task scenarios with independent success criteria and safe synthetic fixtures.
4. Pilot task wording, define consent/recording limits and accessible accommodations.
5. If actual human sessions exist, analyze **provided** notes/results; otherwise provide a runnable plan rather than fabricating results.
6. Extract concrete observations, coded outcomes and bounded descriptive metrics.
7. Cluster root problems; use Part 4C.1 severity and Part 4C.2 accessibility checks only where appropriate.
8. Propose targeted fixes and verification criteria; report limitations and unresolved evidence.

## Safety and privacy

Never ask participants to disclose private recordings/transcripts to complete a test. Do not place identifying research data in Git, issue trackers or AI prompts without authorization.

## Output

Prefer the smallest relevant deliverable: study plan, task cards, finding log or concise report. Do not produce all of them when the user asks for one.
