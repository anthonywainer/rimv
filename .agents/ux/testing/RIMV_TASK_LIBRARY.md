# RimV task and failure-path library

These are **suggested scenarios, not pre-run study results**. Select only the few tasks that answer the current research question. Each task should be adapted to the actual product build and supported platform.

| ID | Scenario to give participant | Observable success | Failure/edge condition |
|---|---|---|---|
| MIC-01 | “Set RimV to use your external microphone.” | Intended input is selected and visible | Device unavailable or renamed |
| PER-01 | “Get RimV ready to capture your voice for the first time.” | Participant handles permission and reaches ready state | Permission denied/restricted |
| CAP-01 | “Start speaking and tell me when RimV is actively listening.” | Correct start, correct interpretation of live state | Slow startup or no input |
| CAP-02 | “Stop this recording now.” | Capture actually stops and UI reflects state | Interruption/stop error |
| TRN-01 | “Speak this provided sample and identify the final text.” | Finds final transcript without mistaking partial text | Long delay, empty transcript |
| TRN-02 | “While transcription continues, read an earlier paragraph.” | Can inspect old text without forced autoscroll/focus loss | Many streaming updates |
| MOD-01 | “Prepare the model needed to transcribe this sample.” | Can identify download/readiness/progress | Insufficient storage or failed download |
| EXP-01 | “Copy your completed transcript into a note.” | Copies expected final text, not stale/partial text | Clipboard failure or empty result |
| EXP-02 | “Export the result to a location you choose.” | Chooses format/location and understands success | Existing filename/conflict |
| REC-01 | “Continue after RimV loses its microphone.” | Recognizes problem and selects recovery | Device disconnected mid-capture |
| AIC-01 | “Find which text was transcribed and which was generated by AI.” | Distinguishes source from AI content | AI result unavailable/failed |
| PRIV-01 | “Find out whether your audio or transcript leaves the device.” | Accurate understanding based on actual product behavior | UI makes unverifiable local-only claim |
| KEY-01 | “Complete the start–stop–copy flow without a mouse.” | Keyboard-only completion | Focus trap or hidden action |
| SR-01 | “Determine whether recording is active using your usual screen reader.” | Understandable state and available stop control | Missing/overly noisy announcement |

## Platform-aware variants

**macOS:** menu-bar status, app activation, microphone permission recovery, shortcuts, selected audio route. **iOS:** touch and large Dynamic Type, interrupted audio sessions, app state changes, safe-area controls. **Windows:** title bar and scaling, system tray, Narrator, input-device switching and permission settings. **Linux:** actual GNOME/KDE toolkit, Wayland/X11, PipeWire/PulseAudio, tray absence, accessible keyboard flows. **Web:** permission prompts, browser zoom, focus, tab order, browser/device changes.

Do not test unsupported functionality or infer future capabilities from directory names.

## Task card recipe

Each selected task should contain: scenario, starting state, realistic fixture, independent success definition, assistance policy, risk/failure variant if in scope, data to capture and platform-specific notes. Keep tasks focused: a formative session usually benefits from a small number of realistic scenarios rather than an exhaustive checklist.
